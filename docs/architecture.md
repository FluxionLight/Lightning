# 架构与状态

## 0.7 输入与移动端

`reader-input.ts` 统一处理 Ctrl+滚轮、WebKit GestureEvent 和 Linux 原生捏合，固定手势开始时的文档，用累计倍率计算正文缩放，并阻止 WebView 整体缩放。Linux 的 `linux_input.rs` 在 GTK 事件层拦截双指 TouchpadPinch，传递位置与倍率给前端；滚动设备来源也传给 `reader-scroll.ts`，以处理高精度触控板与惯性边界。空白桌面的高精度滚动平移 camera，不改变桌面倍率。

`touch-input.ts` 仅接管 touch 指针：单指滚动、释放时的边缘翻页与双指缩放分别管理，双指结束不触发单指翻页；鼠标和笔继续使用原有路径。`mobile.css` 为手机提供底部触控工具、平板提供侧栏，Android 首份文件默认适合宽度的专注阅读。系统栏 Insets 由原生 MainActivity 处理。

Android 的 Kotlin 插件使用系统 ACTION_OPEN_DOCUMENT 选择 PDF，Rust `mobile_files.rs` 将内容 URI 流式导入私有文件，保留原始名称并限制大小，随后继续走统一 PDFium / 阅读状态实现。PDFium 从 APK 原生库加载，Android 不注册桌面 OCR 功能。系统 PNG 保存使用内容 URI 写入；外部原文件不承担阅读状态或临时笔迹存储。

## Ubuntu 分发适配

通用 Tauri 配置与 Windows / Linux 打包配置分离。Linux 把 PDFium 放在 Tauri 资源目录，在 setup 阶段传给 PDF 引擎；原生搜索不依赖启动时的工作目录。Windows 便携目录和开发目录的搜索兼容保留。

Linux 的区域 OCR 使用 `/usr/bin/tesseract`，通过管道传入 PNG 并读回文字，不经过 shell，不创建截图临时文件。中英文语言数据由 `.deb` 的依赖声明安装；PDF 渲染、截图和阅读状态不依赖 OCR 子进程。Linux 原子状态替换使用同目录 rename，沿用写前验证和文件同步。

## 0.6 按实体延展的桌面与主题选项

`lazy-desk.ts` 根据当前展开卡片和实际纸叠的世界包围框计算 camera 可平移范围，至少容纳一屏，再保留 140–260 屏幕像素的外围余量。空桌面有固定范围；收纳对象不参与。平移与整体缩放应用范围约束，不限制文件的世界坐标。文件拖动记录初始 camera，指针靠近边缘时用逐帧位移继续跟进，并补偿 camera 位移保持抓取点；Esc / 失焦同时还原几何与视野。这是实体驱动的浏览边界，不是栅格文件存储或额外的 PDF 加载服务。

新注册文件按当前 camera 和倍率计算屏幕内位置，普通重开仅在原位置完全不可见时移回视野；完整工作区恢复跳过放置步骤，恢复过程中不夹紧半套文件组的范围。默认整理与世界坐标记忆仍独立保存。

`themed-select.ts` 为 OCR、外观与启动设置统一提供 combobox / listbox，保留原 select 作为数据模型，但阻止其鼠标和标签激活，并把焦点交给主题按钮。选项使用应用调色板、圆角及勾选状态，采用顶层 popover（有普通层回退），支持键盘、外部关闭、窗口边缘定位与禁用同步。动态对话框关闭时释放菜单和监听，程序化恢复默认同步更新按钮文本；不依赖第三方 UI 库。

## 0.5.4 纸叠显示与自由坐标

`setReadingMode` 只更新当前文件的模式、纸叠 DOM 与缩略图预取，不再调用 fit / reveal 或刷新主页面。各模式的正文 padding 保持一致，避免专注模式的 ResizeObserver 因显示纸叠重新适配。菜单使用带 aria-pressed 的单个图标按钮，移除原生 select 弹层。

PaperPileLayout 增加可选 `desk:{x,y}`，相对稳定 pileArea 的世界像素偏移，拖动和键盘移动不再夹紧到 0–1。旧 x/y 保留为阅读框和专注模式的归一化位置；缺少 desk 的旧记录在首次桌面显示时按原几何转换，不改正文。新默认纸叠的参考区按当前可视位置创建。界面与 Rust 存储共同校验有限坐标及 ±1e9 的数值上限，新增字段仍在原生单文件阅读状态 v1 中原子保存，兼容旧记录。

重新排布、缩略图完成和临时阅读视图使用固定桌面偏移；主文件的手动移动平移 pileArea，正文滚动与 PDF 缩放不改变它。桌面拖动撤销深拷贝坐标，记忆阅读篇幅保留独立位置，框内拖动继续夹紧。查看全部的世界包围框包含当前显示的实际纸叠。

## 0.5.3 文件目录按钮

每份 DocumentDesk 卡片创建独立 `.document-outline-toggle`，应用工具栏移除目录入口。DocumentOutline 按按钮所属文件路由，不依赖点击前的活动文件；按钮分别维护展开状态及名称，Esc 关闭后返回所属按钮。位置按卡片 / 真实阅读视口计算并补偿桌面倍率，长页滚动时保持按钮在可视区域，完全离开视野的文件不显示孤立按钮。框内按钮位于标题下方，保留标题拖动；专注模式按钮跟随实际可见纸面。框选捕获时临时让出点击区域，标签动画不复制这个控件。

## 0.5.2 文件目录与桌面交互

`DocumentOutline` 按需读取并缓存每个原生文件的目录，将同一个临时面板挂在当前文件卡片上，关闭时移回隐藏工作区，避免全局侧栏挤压桌面。文件位置与 camera 事件更新局部偏移，目录用逆桌面倍率维持文字尺寸；窗口边缘夹紧位置，长页滚动时目录保持在可视区。框内正文和目录分离；专注模式仅为当前文件预留目录宽度。切换文件、收纳、关闭、点击空白或窗口失焦会收起；异步返回核对文件和展开序号，迟到结果不能覆盖其他文件。面板展开状态不持久化，也不进入标签动画快照。

`desktop-interaction.ts` 配合 CSS 禁止桌面原生文字选择及原生图片拖动，消费非编辑区 Ctrl+A，并清除跨工作区的残留 Range；实际输入框与 OCR 文本编辑保留原行为。没有禁用 pointer 交互，PDF 的拖动、纸叠、临时笔和区域捕获继续走原实现。

## 0.5.1 标签过渡与纸叠参考区

`TabTransitions` 对文档和纸叠制作一次不可交互的样式快照，在应用顶层用 transform / opacity 播放 320ms 过渡；真实文件立即切换收纳状态，布局不参与缩放。快照剥离控件身份、临时笔、框选和旧飞行动画，裁切到当前可视区域，保留框内滚动位置。展开先等待目标页渲染；连续点击从当前动画位置反向，关闭、失焦、窗口调整、切换阅读模式或 Esc 会清理，最多同时 4 份快照。系统减少动态效果时直接切换，快照不进入持久化记录。

散纸几何增加可选 `pileArea` 世界坐标参考区，旧布局首次打开时自动补齐。`PaperStack` 以参考区排布，位置相对正文阶段补偿：正文滚动或翻页修改 x/y 时，纸叠的世界位置保持不变；正文缩放也不修改参考区。手动移动整个文件才同步平移参考区，整理和 Home 重设；桌面 camera 继续变换所有对象。参考区随 desk v2 / 完整工作区快照保存；阅读框与专注模式仍使用本地视口，不使用散纸参考区。

## 0.5 收纳、文件组和框内阅读

`DocumentDesk` 的稳定路径布局扩展为收纳标记、每文件 presentation、独立的 frame x/y/width/height，以及 frame / focus 页内比例。散纸仍使用原 x/y/width；框的大小与正文宽度分开，拖标题移动框、拖手柄调整矩形，正文用真正的 overflow 视口裁切。框内翻页继续使用阅读器原有 scrollHeight/clientHeight 落点，排除原生滚动条占据的空间；散纸仍按桌面实际可视边界滚动。PaperStack 在框内采用视口坐标，在散纸旁采用桌面坐标。

标签收纳隐藏对象而不关闭原生句柄，重展开恢复当前页和内部位置；全部收纳时 activeId 可以为空但 tabs 仍存在。关闭当前文件优先选择未收纳的相邻文件。隐藏文件不做后台页面补全，展开后按目标页恢复渲染。目录、画笔与框选随当前阅读表面绑定。

`WorkspaceSession` 使用独立 `lightning.workspace.v1`，一次 localStorage 替换提交启动偏好、标签路径顺序、当前稳定 ID 和完整桌面快照。原生逐文件阅读状态保持为页码、倍率、形式、纸叠与锚点的权威来源，避免用过时工作区快照复活已消费锚点。恢复期间暂停保存中间空桌面，恢复完成后保留缺失文件条目并更新实际状态；正常关闭先 flush 阅读记录再保存工作区。

自动恢复默认关闭。启用后的 resume / first 只决定启动组的当前页和页内比例，摆放与形式保留；明确的启动文件优先。专注与框内位置分别记忆，跨模式、收纳和进程重启均按比例恢复。旧 desk v2 没有新字段时默认为散纸和未收纳，旧阅读记录不做格式迁移。

## 0.4.1 按文件缩放与独立纸叠

Ctrl+wheel 在桌面层让给阅读器，由鼠标坐标命中正文后交给 `PdfViewer.zoomDocument`，在异步渲染前固定文档。`DocumentDesk.resizePaper` 只改变该纸的几何，以鼠标下方内容为缩放原点；camera 不变。空白与旁页纸叠上的 Ctrl+wheel 会被消费，避免退回整个场景或 WebView 缩放。

`PaperStack` 在桌面中用工作区范围约束预览，并使用固定默认宽度；显式宽度独立保留，不随主纸宽高变化。专注模式继续使用原有随视口变化的纸叠约束。主文档同页刷新位图时保留图片和临时笔表面 DOM，只更新像素、尺寸和 SVG viewBox；旁页只重排位置，避免连续缩放反复替换滚轮目标和预览。

## 0.4 侧栏与桌面阅读边界

`reader-shell.ts` / `reader-shell.css` 提供 40px 单行标签栏、自绘窗口三键、应用折叠菜单、默认展开的阅读图标栏与暂时状态提示。Tauri 禁用原生额外标题栏，窗口操作仅授权本窗口的拖动、最小化、恢复、最大化和关闭。自绘关闭键使用 closeRequested 原保存收尾流程。`icons.ts` 用本地 SVG 线条图标，按钮保留名称与提示。

`DocumentDesk.scrollPaper` 将鼠标下方纸张按屏幕滚轮距离换算到世界坐标，仅修改该文档的 x/y；camera 和其他纸张不动。可视范围由工作区实际 bounds 得到，排除标签栏和工具栏。纸张尚有隐藏内容时先滚动，到边界后才翻页。render 提交真实页尺寸后再按 start / end 对齐可视上缘 / 下缘；小纸张正常摆放不被每次翻页重置。

`PdfViewer.turnDocument` 在异步渲染前固定目标文档，避免鼠标跨文件时把旧滚轮导航投递给新选中的文件。桌面锚点读取可视边界相对纸张的比例；画笔与截图也裁切到实际可视区域。每次渲染记录真正请求的倍率，并在横竖页切换时按真实 point 宽度重新选取位图，避免 camera 改变或混合尺寸造成误报清晰度。

## 0.3 无界桌面与外观

`DocumentDesk`（`src/document-desk.ts`）管理世界坐标中的多个真实 PDF 页面。每张纸的边界就是 PDF 边界，宽度来自摆放几何，高度按当前页真实 point 尺寸计算。桌面不存在独立文档窗口、内部滚动条或正坐标边界；一台 camera 通过 translate + scale 改变视野，纸张 x/y 可为负数。专注模式才恢复常规可滚动视口。Reader 把临时笔与框选绑定到当前纸张，每份文档各有独立 PaperStack，旁页可持续同屏显示；关闭时取消动画、释放指针与全局监听。

前台调度继续优先响应最新目标。失去焦点时尚未完成的页面，按文档归属与序号在后台完成；被新的导航打断时丢弃过时提交。后台保留原导航的 start / end / preserve / anchor 位置意图。关闭任何表面会释放该文档与缓存；即使相邻文件显示失败，也移除已关闭的表面。

桌面整体缩放与纸张宽度、专注阅读 zoom 分开保存；桌面渲染分辨率按纸张宽度和设备像素比计算，仍使用有界缓存及原生像素预算。纸叠动画、拖动、临时笔与框选补偿 camera 缩放。平移、移动纸张等几何操作取消未完成框选。`lightning.desk.v2` 保存工作区模式、camera、桌面倍率与按稳定文档 ID 索引的 x/y/width/z，最多保留 200 份布局；读取旧 v1 时迁移位置和宽度，舍弃窗口高度。「查看全部」由所有纸张的世界坐标外包围框计算视野。

`AppearanceManager`（`src/appearance.ts`）生成主题色派生的表面、强调色容器和边界色，通过 CSS 变量应用 Material 圆角设计。对话框预览可取消，保存按顺序提交。`src-tauri/src/appearance.rs` 提供加载 / 原子保存外观及有界图片导入。图片只在本机解码和压缩，不用路径 URL 直接加载外部文件，也没有网络图片请求。外观配置和 JPEG 背景副本位于独立的 `appearance.json`，不占用 PDF 阅读状态或 WebView localStorage 图片配额。

## 三层状态

文档状态版本 1：`schemaVersion`、`documentId`、`pdfPath`、`page`、`zoom`、`fitMode`、`readingMode`、`paperLayout`、`paperReadingViews`、`anchor`。原生规范路径在 Windows 下统一大小写与分隔符后 SHA-256，作为稳定文件名；身份按路径，不声称跨移动内容指纹。

状态在 Tauri `app_data_dir()/reading/<documentId>.json`。前端 350ms 去抖，按文件串行保存，关闭前 flush；写入先验证，临时文件与正式文件同目录，flush + sync 后 Windows MoveFileExW 替换并请求写穿。已有文件若损坏或版本不支持，不覆盖。重新回到已保存状态时取消旧快照，防止已消费锚点被旧写入复活。

应用偏好使用独立 WebView localStorage 命名空间：`lightning.shortcuts.v1`、`lightning.pdf-laser.v1`、`lightning.capture-mode.v1`。读失败回默认；写失败保留本次设置并说明未保存。

原生句柄、任务队列、缓存、飞行克隆、手势、临时预览、预览滚动、SVG 路径、计时器、捕获请求只存在内存，不序列化到阅读状态或 PDF。

## 渲染与几何

baseScale 为 2，与 CRH 约定一致。用户倍率对应逻辑显示尺寸，持续适配逐页使用真实 point 尺寸和实际 padding 重新计算。原生位图限制为最多约 16M 像素、宽 12000 / 高 20000；极高倍率下保留显示大小，采用有界分辨率，避免无界分配。

每次渲染固定文档、页码、序号，必要时按页面新尺寸重算适配，再 await 图片 decode，核对序号和归属后才替换主页面。位置意图为页首、页尾、保持比例或锚点双轴比例。迟到或关闭文档结果不提交。

缓存估算 Base64 JS 字符约 32MiB、最多 12 项；这不是 GPU / 解码总内存预算。主任务优先，只有附近页面预取；纸叠最近邻页按宽度选择清晰度档位，远页用小缩略图。动画只操作已解码图层，飞行克隆最多 4 张，支持减少动态效果。动画完成会刷新稳定状态，使锚点等操作恢复可用。

## 区域捕获适配

独立版采用本地右侧结果面板，这是 Lightning 新增的消费者，原 CRH 聊天投递没有迁移。固定 tabId、pageIndex、阅读形式、捕获方式、请求序号；来源变化后丢弃旧结果。PNG 在原 PDF 上渲染到目标宽 2400，再按归一化矩形精确裁切；上游仍受位图预算约束，单结果 PNG 上限 24MiB。

截图流程不调用 OCR。OCR 使用系统 Windows.Media.Ocr，输入按系统最大尺寸等比缩小；先尝试简体中文语言，再退回用户系统语言。结果 trim 首尾，保留内部换行。捕获不读取桌面或整窗，不包含临时笔迹，也不发送网络请求。
